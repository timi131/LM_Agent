# LM Agent

Локальный LLM-агент на базе [Ollama](https://ollama.com): модель сама решает, когда вызвать инструмент (tool calling), получает результат и продолжает рассуждение до итогового ответа. Модель работает локально; в сеть агент выходит только через инструменты (поиск, страницы, API, почта).

## Быстрый старт

```bash
ollama pull qwen2.5:7b
ollama pull embeddinggemma     # для поиска по документам
uv sync
uv run playwright install chromium   # для браузера; не нужно, если есть Google Chrome
cp .env.example .env           # и раскомментируйте нужное
uv run lm-agent-web            # веб-чат: http://127.0.0.1:8000 (+ расписание и Telegram-бот)
uv run lm-agent                # чат в терминале
uv run lm-agent "Сколько будет sqrt(2) * 10?"   # разовый запрос
uv run lm-agent -t basic,web   # только выбранные наборы инструментов
uv run lm-agent -m llama3.1:8b # другая модель
```

Команды в чате: `/tools`, `/memory`, `/reset` (очищает диалог, но не память), `/exit`.

## Веб-чат

```bash
uv run lm-agent-web                    # http://127.0.0.1:8000
uv run lm-agent-web --port 8080 -t basic,web,docs
```

Чат в браузере показывает каждый вызов инструмента (раскрывается — видно результат). **Панель «Браузер»** справа показывает экран браузера агента вживую и открывается сама, когда агент начинает действовать на сайте. По панели можно кликать, печатать, прокручивать и вводить адрес. Так, например, можно самому войти на сайт, после чего агент будет работать уже под вашим входом. В веб-режиме отдельное окно Chrome не открывается (если нужно и оно, задайте `LM_AGENT_BROWSER_HEADLESS=0`). Опасные действия приходят карточкой с кнопками «Разрешить / Отклонить»; без ответа 5 минут — отклоняется. Справа — панели «Память» (просмотр, добавление, удаление фактов) и «Документы» (загрузка перетаскиванием, удаление, переиндексация). Диалог переживает перезагрузку страницы, но не перезапуск сервера; «Новый чат» очищает диалог, память остаётся.

**Голосовой ввод.** Нажмите 🎤 рядом с полем ввода и говорите. Чтобы закончить, нажмите кнопку ещё раз или Enter; Esc отменяет запись. Запись распознаётся на этом компьютере тем же локальным Whisper, что и голосовые в Telegram, а текст появляется в поле ввода: его можно поправить перед отправкой. Браузер разрешает микрофон только на `http://127.0.0.1`/`localhost` или по https. Если сервер открыт по сети через http, микрофон работать не будет.

**HTTP API** для своих программ и ботов (интерактивная документация — `/api/docs-ui`):

```bash
curl -s localhost:8000/api/chat -H 'Content-Type: application/json' \
  -d '{"message": "Сколько будет 2**10?", "session": "bot-1"}'
# → {"answer": "...", "tools": [...]}
```

Через API подтверждать некому, поэтому опасные действия там отклоняются, если не включён `LM_AGENT_AUTO_APPROVE`. Остальные методы: `POST /api/transcribe` (аудиофайл → текст), `GET/POST /api/memory`, `DELETE /api/memory/{id}`, `GET/POST /api/docs`, `DELETE /api/docs/{имя}`, `POST /api/docs/reindex`, `POST /api/sessions/{id}/reset`, `GET /api/info`.

**Доступ из локальной сети (Wi-Fi).** Так агентом можно пользоваться с телефона, планшета или другого компьютера.

1. Задайте токен доступа в `.env`, без него сервер в сеть не откроется:
   ```
   LM_AGENT_WEB_TOKEN=…   # python3 -c "import secrets; print(secrets.token_urlsafe(16))"
   ```
2. Запустите `uv run lm-agent-web --lan --https`. Сервер напечатает адреса вида `https://192.168.1.47:8000` и `https://ИмяMac.local:8000`.
3. Откройте этот адрес на другом устройстве. Браузер один раз предупредит о непроверенном сертификате: это ваш собственный сертификат, нажмите «Подробнее → Всё равно перейти». Затем введите токен на экране входа.

`--https` нужен для микрофона: по обычному http браузеры не дают странице доступ к микрофону, если она открыта не с `localhost`. Без микрофона можно запускать просто с `--lan`. Сертификат выпускается автоматически в `~/.lm_agent/tls` на все адреса Mac в сети и перевыпускается, если адрес сменился. Включить HTTPS по умолчанию можно через `LM_AGENT_WEB_HTTPS=1`. Пока чат открыт с другого устройства, Mac должен быть включён и не спать.

**Безопасность.** По умолчанию сервер слушает только `127.0.0.1`. Запросы с чужих сайтов, открытых в том же браузере, отклоняются (проверка `Origin`). При открытии в сеть (`--lan` или `--host 0.0.0.0`) сервер требует `LM_AGENT_WEB_TOKEN`: у агента есть shell и доступ к файлам. Программы передают токен заголовком `X-Token`. В браузере он вводится на экране входа (или передаётся один раз ссылкой `…/?token=…`, после чего сразу убирается из адреса) и запоминается.

## Задачи по расписанию

В заданное время агент выполняет запрос и присылает результат: во вкладку «Задачи» веб-чата и в Telegram, если бот подключён. Поставить задачу можно тремя способами:

- **словами в чате** (веб или Telegram): «каждый будний день в 9 утра делай сводку по таблице заявок…». Агент вызовет `schedule_task`, а вы подтвердите;
- **формой** во вкладке «Задачи»;
- **через API**: `POST /api/schedule {"when": "будни 09:00", "prompt": "…", "name": "…"}`.

Время задаётся так: `09:00`, `каждое утро в 9`, `будни 09:00`, `выходные 10:00`, `пн,ср 18:30`, `каждый час`, `каждые 15 минут` или cron из пяти полей. Задача — это запрос словами, поэтому при каждом запуске агент заново смотрит свежие данные: таблицу, документы, API сервиса, сайт. Подтверждать действия во время задачи некому, поэтому опасные действия в ней отклоняются, если не включено `LM_AGENT_AUTO_APPROVE`.

Задачи хранятся в `~/.lm_agent/schedule.json` вместе с последними 10 результатами и списком вызванных инструментов. **Расписание работает, пока запущен сервер** (`lm-agent-web` или `lm-agent-bot`). Пропущенные, пока сервер был выключен, запуски не догоняются.

## Telegram-бот

1. Создайте бота у [@BotFather](https://t.me/BotFather) (`/newbot`) и получите токен.
2. Пропишите его в `.env`:
   ```
   TELEGRAM_BOT_TOKEN=123456:ABC...
   TELEGRAM_ALLOWED_USERS=123456789,@username
   ```
   Если вы не знаете свой id, напишите боту что угодно: чужим он отвечает только «Нет доступа. Ваш Telegram id: …».
3. Запустите `uv run lm-agent-web`: бот стартует вместе с веб-чатом. Если нужен только бот (например, на сервере), запустите `uv run lm-agent-bot`.

Что умеет бот:
- тот же агент со всеми инструментами и долговременной памятью;
- опасные действия подтверждаются кнопками «✅ Разрешить / ✖️ Отклонить»;
- пока агент работает, бот показывает статус «печатает…» и список вызванных инструментов;
- задачи, поставленные из Telegram, присылают результат в тот же чат, остальные — всем разрешённым пользователям.

**Голосовые сообщения.** Голосовые, аудиофайлы и видеокружки распознаются локально через [faster-whisper](https://github.com/SYSTRAN/faster-whisper), без интернета и сторонних сервисов. Бот показывает распознанный текст («🎤 …») и отвечает на него как на обычное сообщение. При первом голосовом скачивается модель распознавания (`small`, около 480 МБ) в `~/.lm_agent/whisper`. Настройки:
- `LM_AGENT_WHISPER_MODEL`: `tiny` / `base` / `small` (по умолчанию) / `medium` / `large-v3`. Чем больше модель, тем точнее и медленнее. `off` выключает распознавание.
- `LM_AGENT_WHISPER_LANGUAGE`: язык речи, по умолчанию `ru`. `auto` включает автоопределение, но на коротких фразах оно часто ошибается.
- `LM_AGENT_WHISPER_PROMPT`: подсказка со словарём. В неё входят слова, которые часто звучат в работе (по умолчанию REDSMS, SMS, заявка, ответственный, OkoCRM, операторы и т. п.), и Whisper пишет их правильно. Чтобы отключить подсказку, задайте `-`.

Длина голосового — до 10 минут.

Команды бота: `/reset` (начать заново), `/tasks` (задачи по расписанию), `/id`. Бот работает через long polling, поэтому внешний адрес и вебхуки не нужны. Если Telegram недоступен напрямую, задайте `TELEGRAM_PROXY=http://…` или `socks5://…`.

**Безопасность:** у агента есть shell и доступ к файлам. Добавляйте в `TELEGRAM_ALLOWED_USERS` только тех, кому доверяете этот компьютер.

### Подтверждения

Перед опасным действием агент показывает, что именно собирается сделать, и спрашивает `Разрешить? [y/N]`. Если терминал не интерактивный (скрипт, cron), такие действия отклоняются. Флаг `-y` или `LM_AGENT_AUTO_APPROVE=1` отключает вопросы. Включайте это, только если доверяете модели и всем источникам, которые она читает: текст веб-страницы или письма может подтолкнуть модель выполнить чужую команду.

### Браузер

Агент управляет настоящим Chromium через Playwright: выполняет JavaScript, кликает, заполняет формы, переключает вкладки. Модель видит страницу текстом — списком элементов с номерами (`[12] button "Войти"`) и видимым текстом; действия ссылаются на номер.

Если установлен Google Chrome, ничего скачивать не нужно: агент запустит его с отдельным профилем. Иначе установите Chromium (один раз):

```bash
uv run playwright install chromium
```

Выбор браузера — `LM_AGENT_BROWSER_CHANNEL`: `auto` (Chromium, если скачан, иначе Chrome), `chromium`, `chrome`, `msedge`.

- **Где смотреть:** в веб-чате — панель «Браузер» (живой экран, можно кликать и печатать). В терминальном режиме открывается обычное окно Chrome. Режим без окна: `LM_AGENT_BROWSER_HEADLESS=1`.
- **Отдельный профиль** в `~/.lm_agent/browser`, не ваш Chrome. В нужные сайты войдите сами в окне агента один раз — сессия сохранится. Агент **не вводит пароли**: в поля пароля он писать отказывается.
- **Подтверждения** (`LM_AGENT_BROWSER_CONFIRM`): `risky` (по умолчанию) — перед кнопками, отправляющими форму, Enter для отправки и кнопками со словами вроде «Оплатить», «Удалить», «Отправить», «Подтвердить»; `all` — перед любым кликом и вводом; `none` — никогда. В запросе показывается, что это за элемент и на какой странице.
- Старые снимки страниц в истории автоматически сокращаются, чтобы не переполнять контекст.
- Скриншоты (`browser_screenshot`) сохраняются в `workspace/screenshots/` — они для вас, `qwen2.5:7b` картинки не видит.
- Модель на 7B уверенно проходит сценарии в 3–5 шагов; на длинных сценариях полезна модель крупнее.

### Файлы

Относительные пути считаются от `workspace/`. Абсолютные пути и `~/…` разрешены только внутри папок из `LM_AGENT_FILE_ROOTS` (по умолчанию — домашняя папка). Чтение в этих папках идёт без вопросов, запись вне `workspace/` требует подтверждения.

### Внешние сервисы (CRM, API)

Скопируйте `services.example.json` в `services.json` и опишите сервисы:

```json
{
  "okocrm": {
    "description": "OkoCRM: сделки, контакты, задачи",
    "base_url": "https://api.okocrm.com/v2",
    "headers": {"Authorization": "Bearer ${OKOCRM_TOKEN}"}
  }
}
```

`${VAR}` подставляется из окружения или `.env` на стороне агента, поэтому модель токенов не видит. Адрес `base_url` в примере нужно сверить с документацией сервиса. Для разовых запросов к любому API есть `http_request`.

### Почта

Заполните в `.env` поля `EMAIL_ADDRESS`, `EMAIL_PASSWORD` (пароль приложения, а не основной), `IMAP_HOST` и `SMTP_HOST`. Письма читаются без пометки «прочитано».

### Поиск по документам

Положите файлы в `docs/` (или укажите `LM_AGENT_DOCS`). Поддерживаются `.md .txt .pdf .docx .xlsx .html .csv .json` и исходный код. Индекс строится на эмбеддингах `embeddinggemma` и хранится в `~/.lm_agent/doc_index.json`. При каждом поиске пересчитываются только новые и изменённые файлы.

### База знаний из других проектов

Агента не нужно «дообучать». Базы знаний подключаются к поиску по документам: перед ответом агент сам находит нужную статью и отвечает по ней. В `.env` перечислите папки или файлы через `:`:

```
LM_AGENT_KNOWLEDGE=~/Desktop/ddd/knowledge/faq.md:~/Desktop/ddd/knowledge/nashi-uslugi.md
```

Источники подключаются только на чтение: файлы остаются на своём месте, а их изменения агент подхватывает сам при следующем поиске. Каждый формат разбирается по-своему:
- **Markdown с заголовками** (например, FAQ) режется по статьям, по одному фрагменту на вопрос с названием раздела. Поэтому поиск находит ровно нужную статью, а не обрывок двух соседних.
- **JSON-список записей** (например, шаблоны ответов `{keywords, answer}`) и **построчный JSON** (`{category, question, answer, metadata}`, формат определяется по содержимому, даже если файл называется `faq.md`) разбиваются по одному фрагменту на запись, вместе с пометками вроде «требует проверки» и «уточнить».
- **PDF без текстового слоя** (сканы, «печать в PDF» картинками) распознаётся встроенным в macOS движком Vision, русский и английский, без интернета.
- Word, обычные PDF, таблицы и прочее индексируются как обычно.

Перед каждым вопросом агент сам ищет в подключённых базах (только в `LM_AGENT_KNOWLEDGE`, без выгрузок и загруженных документов) и передаёт модели до трёх подходящих статей (сходство от 0,55). Модель отвечает по ним. Если в статье стоит «требует проверки: да», она говорит, что ответ нужно уточнить у специалиста, а данные из пункта «Уточнить» просит у пользователя. Если подходящих статей нет, модель работает как обычно своими инструментами. Поиск можно вызвать и вручную (`search_documents`): он идёт и по `docs/`.

### Таблицы (CSV, Excel)

На вопросы вида «сколько», «кто чаще всего», «среднее время ответа» или «список по условию» поиск по смыслу не ответит: он видит лишь несколько фрагментов. Поэтому таблицы из `docs/` и `workspace/` загружаются в DuckDB, и модель отвечает SQL-запросом к таблице `t`. Сначала `table_info` показывает колонки и примеры значений, затем `table_query` выполняет запрос. Файл можно указать номером, частью имени или полным именем. SQL работает только с этой таблицей: читать и писать другие файлы, ходить в сеть и менять настройки из запроса нельзя.

В поиск по смыслу таблицы попадают построчно, с названиями колонок (`Тема: …; Статус: …`). Так «найди заявки, где не приходят SMS» находит конкретные строки.

Агент знает, какие файлы загружены: их список подставляется в системный промпт.

### Документы и отчёты (Word, PDF, Excel)

Попросите словами: «сделай отчёт в Word по заявкам», «PDF-справку по…», «выгрузи в Excel заявки по ответственным». Есть три инструмента:
- `create_document` пишет отчёт в Markdown и сохраняет его как **Word**, **PDF** или **Excel** (`format`). В файле будут заголовки, списки, таблицы и жирный шрифт. PDF печатается через Chrome, поэтому кириллица и таблицы выглядят правильно. JavaScript и выход в сеть при печати отключены.
- `create_spreadsheet` делает Excel из CSV или Markdown-таблицы. Шапка жирная, ширина колонок подбирается по содержимому, первая строка закреплена, числа сохраняются числами.
- `export_query` выгружает результат SQL по вашей таблице прямо в Excel. Все строки и числа берутся из данных, модель их не переписывает и не может в них ошибиться. Это лучший способ «выгрузить в Excel».

Файлы сохраняются в `workspace/reports`. В веб-чате у созданного файла появляется карточка с кнопкой «Скачать». Telegram-бот присылает файл в чат, в том числе если отчёт сделала задача по расписанию. Готовые отчёты не считаются исходными таблицами: агент не будет «анализировать» свою же сводку вместо настоящей выгрузки.

### Память

`remember` сохраняет факты в `~/.lm_agent/memory.json`. При каждом запуске они попадают в системный промпт. Просмотреть память можно через `/memory`, удалить запись — попросив агента «забудь #N».

## Выбор модели и ограничения

- `qwen2.5:7b` справляется с цепочками инструментов, памятью и поиском по документам.
- `llama3.1:8b` вызывает все инструменты разом и подставляет пустые значения. Годится только для простых запросов с одним инструментом.
- Модель на 7B параметров в веб-задачах часто довольствуется сниппетами поиска и отвечает по своим устаревшим знаниям. Надёжнее дать ей конкретную ссылку («открой …») или взять модель крупнее (например, `qwen2.5:14b`).
- Чем меньше инструментов, тем точнее модель их выбирает. Для узких задач включайте только нужные наборы через `-t`.

## Скорость

На Apple M4 модель `qwen2.5:7b` читает промпт со скоростью около 165 токенов/с и пишет ответ со скоростью около 20 токенов/с. Поэтому основное время уходит на **чтение** всего, что модель получает:

- **Описания инструментов**: около 2,7 тыс. токенов, это примерно 17 с. Агент прогревает их при старте чата и сервера, и Ollama их кэширует. После прогрева первый ответ приходит меньше чем через секунду. Кэш сбрасывается, когда меняется системный промпт (например, после `remember`). Если включить через `-t` только нужные наборы, промпт станет короче.
- **Страницы**: снимок браузера содержит только видимую часть, около 1,5 тыс. токенов, это примерно 10 с. Длинный текст читается частями через `browser_read_page` и `fetch_url(part=…)`.
- **Ответ** выводится потоком по мере генерации. В веб-чате под ответом показано, сколько он занял.

Если нужно ещё быстрее: модель `qwen2.5:3b` работает примерно вдвое быстрее, но хуже справляется с инструментами. Можно также включить в Ollama `OLLAMA_FLASH_ATTENTION=1`, это ускоряет чтение длинного контекста.

## Свой инструмент

Подойдёт обычная функция с аннотациями типов: схема для модели строится из сигнатуры и докстринга.

```python
import ollama
from lm_agent import Agent, Settings
from lm_agent.toolkits import build_registry

settings = Settings.from_env()
client = ollama.Client(host=settings.host)
tools, memory = build_registry(settings, client, enabled=("basic", "memory"))

@tools.register
def get_weather(city: str) -> str:
    """Возвращает погоду в городе.

    city: название города
    """
    return f"В {city} +5°C, облачно"

# @tools.register(confirm=True) — спрашивать пользователя перед каждым вызовом
# (approver передаётся в build_registry; без него такие вызовы отклоняются)

agent = Agent(client=client, tools=tools, settings=settings, context=memory.as_prompt)
print(agent.ask("Какая погода в Казани?"))
```
